**Изменено:**

**Серверной работы НЕ потребовалось** — endpoint `GET /api/books/search?q=` уже был в `server/src/routes/books.js` (с задачи 2.2). MongoDB text index на `title + author + description` в `server/src/models/Book.js` уже есть.

**Новых pub-пакетов НЕ потребовалось** — `Timer` из `dart:async` встроен в SDK.

**Поведение (соответствует STEP-BY-STEP задача 2.5):**
- Юзер тапает на лупу в шапке каталога → `/search`
- Автофокус на поле, клавиатура открывается сразу
- Каждое нажатие клавиши → `updateQuery()` → состояние `typing` (shimmer) + сброс таймера
- Через 300ms тишины → запрос на сервер → `loading` (shimmer) → `success` (сетка)
- Пустой ввод → state идёт обратно в `idle` → показывается подсказка «Найдите разбор»
- Крестик в поле → очищает + state идёт в `idle`
- При сетевой ошибке → ErrorView с retry (повторяет последний запрос)
- При success + 0 результатов → «Ничего не нашли по запросу X. Попробуйте другие слова»
- Race condition guard: если за время запроса юзер поменял query — результат игнорируется
- Карточки результатов — те же `BookGridCard` что в каталоге (тап → /book/:id)

**Что НЕ сделано в 2.5-поиск (отложено):**
- ❌ «Недавние запросы» — упоминается в MASTER 4.11 но не в STEP-BY-STEP. Требует SharedPreferences. Post-MVP.
- ❌ «Популярные запросы» — нужен API endpoint для топа поисковых запросов. Post-MVP.

## ❗ ВАЖНОЕ ДЛЯ БУДУЩИХ ЗАДАЧ

**1. Локализация цен (Фаза 3)**

В каталоге, на главной и на экране книги **сейчас** жёстко в долларах ($24.99, $29.99, $44.99) — это **временная заглушка**. Берётся из поля `BookModel.priceUsd` через геттер `displayPriceUsd`.

**В Фазе 3** (задачи 3.1, 3.2):
- Анна создаёт IAP продукты в App Store Connect и задаёт **Apple Price Tier** для каждого
- Подключаем StoreKit 2 (`in_app_purchase`)
- В UI заменяем `book.displayPriceUsd` на `Product.displayPrice` от StoreKit — Apple возвращает **локализованную строку** в валюте Apple ID юзера (₽ для региона Russia, ₺ для Turkey, ₸ для Kazakhstan и т.д.)
- Apple конвертирует валюты сам, обновляет курсы каждые 6 месяцев — нам не делать

**2. Non-consumable IAP для книг и пакетов (пробел в плане)**

В STEP-BY-STEP Фаза 3 говорит про **подписки** (`club.basic.*`, `club.premium.*`), но прямо отмечает: «Non-consumables: пока не создаём (нужны конкретные book_id)».

Когда дойдём до Фазы 3 — оформить как **задачу 3.5: Non-consumable IAP для отдельных книг и пакетов**:
- 42 книги × Product ID = `book.{slug}` (например `book.anna_karenina`)
- 6 пакетов × Product ID = `package.{slug}` (например `package.tolstoy`)
- Маппинг `priceUsd` → ближайший Apple Price Tier
- Поле `appleProductId` в схеме Book уже есть (см. модель)

**3. Кнопка «Купить на сайте» — УДАЛЕНА (Apple compliance)**

Кнопка была временно добавлена в задаче 2.6 и **удалена в той же сессии** после проверки актуальных правил Apple:
- Послабления Apple Guideline 3.1.1(a) (апрель-май 2025) действуют **только на US storefront**
- Наша аудитория Россия/СНГ → старые правила: внешние ссылки на покупки запрещены, риск reject при ревью
- Альтернатива — задача 3.6 (см. пункт 7 ниже).

В `book_screen.dart` оставлен комментарий в `_PaidActions` объясняющий что здесь только Apple IAP и превью, без внешних ссылок.

**4. Заглушки на экране книги (2.6)**

В `_BookContent` есть 3 захардкоженных значения:
```dart
static const bool _isPurchased = false;
static const Set<int> _listenedPartNumbers = <int>{};
static const double _progressPercent = 0.0;
```
**Не путать с моками сервисов** — это просто три boolean/int, которые в Фазе 3 / после 2.7 заменятся на `ref.watch(...)`. Никаких файлов-моков, классов-плейсхолдеров и фейковых провайдеров.

**5. Конвертация BYN→USD при seed — приближённая, не финальная**

В `server/src/scripts/seed.js`, функция `bynToUsd()`, четыре фиксированных тира:
- 80 BYN → $24.99 (~$24.46 по курсу мая 2026)
- 100 BYN → $29.99 (~$30.58)
- 150 BYN → $44.99 (~$45.87)
- 280 BYN → $84.99 (~$85.63, для пакетов)

Курс в скрипте захардкожен 3.1 BYN/$ (устаревший на ~5%), и комментарий «округление к Apple Price Tier» в коде — **неточен**: настоящие Apple Tier'ы выбираются вручную в App Store Connect из дискретной таблицы ~800 значений. Наши значения совпадают с валидными Apple-тирами (Tier 25, 30, 45, 85), но это совпадение хороших круглых цен, а не алгоритм.

**Финальные цены назначит Анна** в App Store Connect (задача 3.1, Фаза 3). До этого `priceUsd` в БД — временная заглушка для UI.

**6. ❗ ВОПРОС К АННЕ — эксклюзивные книги внутри пакетов (блокирует задачу 2.5.5)**

## ПРАВИЛА КОДА

- НЕ создавать заглушки-классы. Файл создаётся только когда пишется его реализация. Допустимы 1-2 строки хардкода прямо в build-методе (см. _BookContent в 2.6).
- AI-CONTEXT обновлять В ТОМ ЖЕ КОММИТЕ что и код (или сразу после, как в 2.6 — отдельным коммитом, но в той же сессии).
- Схема Book — источник истины `server/src/models/Book.js`, НЕ MASTER 7.3 (см. «РАСХОЖДЕНИЯ»).
- `coverImageUrl` с префиксом `asset://` обрабатывается виджетом `BookCoverImage`.
- Цены в UI пока из `book.priceUsd` (USD жёстко). В Фазе 3 заменим на `Product.displayPrice` от StoreKit (локализовано Apple).
- Категории — `core/constants/book_categories.dart` (одна точка изменения).
- **При багах: запросить полный лог терминала, прочитать ПЕРВУЮ ошибку, одна правка по делу. НЕ гадать наугад.** (См. УРОК ПО ДЕБАГУ)
- **Для UX-проблем (визуал): спросить юзера КАК должно выглядеть, прежде чем править**. Скриншот или словесное описание. Иначе цикл «правка → опять не так» (см. историю обложки 2.6).
- **Apple compliance: при любом упоминании внешних ссылок/платежей — перепроверить свежие правила через web_search (минимум 2025+)**. Не полагаться на память. Послабления Apple меняются каждые несколько месяцев и часто действуют только в US storefront.
- **Flutter 3.22.3 — `withOpacity()`, не `withValues()`** (последний доступен с 3.27+).
- **Согласовывать ДО написания кода:** новые пакеты не из спеки, варианты архитектуры (A/B). Не угадывать — спрашивать.
- **Если задача зависит от ответа заказчика (как 2.5.5) — ставить на паузу, не угадывать.** Зафиксировать вопрос в AI-CONTEXT, продолжать другими задачами.
