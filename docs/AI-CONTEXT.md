## 🎧 АУДИО-СТРИМИНГ (ПАМЯТКА — задача 2.3 + 2.7)

### Архитектура

Стандартный подход (как у Audible, Spotify, Apple Music):

```
Flutter (плеер)                       Express (бэкенд)
     │                                       │
     │  GET /api/books/:id/audio/:partNumber │
     │ ────────────────────────────────────► │
     │                                       │
     │  ◄────  { audioUrl, duration, partNumber, ... }
     │         signed URL, TTL 1 час         │
     │                                       │
     │  GET /audio/...?exp=...&sig=...       │
     │  + Range: bytes=0-1000                │
     │ ────────────────────────────────────► │
     │                                       │ verifySignedUrl()
     │  ◄────  206 Partial Content + MP3     │
```

Протокол подписи: **HMAC-SHA256**. Ключ: `AUDIO_SECRET` в `.env` (мин 32 символа).
Format URL: `http://host:port/audio/<filename>?exp=<unix>&sig=<hex>`.
Коды: 200, 206, 403, 410, 404, 416.

### Где лежат файлы

| Среда | Путь |
|---|---|
| **Mac (разработка)** | `~/Chitatel_app/audio-storage/<book_slug>/part-<N>.mp3` |
| **VPS (продакшен)** | `/var/audio/chitatel/<book_slug>/part-<N>.mp3` |

`audio-storage` на одном уровне с `server/` и `app/`. **НЕ в git**.

### `.env` для Mac

```bash
AUDIO_SECRET=dev-audio-secret-CHANGE-IN-PROD-min-32-chars
AUDIO_BASE_PATH=/Users/g/Chitatel_app/audio-storage
AUDIO_URL_TTL_SECONDS=3600
PUBLIC_BASE_URL=http://localhost:3000
```

### Миграция на VPS — три строки

```bash
AUDIO_SECRET=<generate via: openssl rand -hex 32>
AUDIO_BASE_PATH=/var/audio/chitatel
PUBLIC_BASE_URL=https://api.chitatel.app
```

Перенос: `rsync -avz --progress ~/Chitatel_app/audio-storage/ user@vps:/var/audio/chitatel/`

### Как добавить новые MP3

1. Положить в `~/Chitatel_app/audio-storage/<slug>/part-1.mp3` ... `part-N.mp3`
2. ffprobe длительности: `for f in part-*.mp3; do d=$(ffprobe -i "$f" -show_entries format=duration -v quiet -of csv="p=0"); echo "$f: ${d%.*} сек"; done`
3. Добавить в `seed.js` массив `<BOOK>_PARTS`
4. `cd ~/Chitatel_app/server && npm run seed`

**ВАЖНО:** MP3 строго (не OGG, не M4A). ffmpeg через evermeet.cx (не brew).

## 🐛 БАГ САХРАНЕНИЯ ПРОГРЕССА — ДИАГНОЗ 13.05.2026

**Симптом:** «части переключаются, но позиция не запоминается между сессиями».

**Корневая причина:** клиент шлёт POST `/api/progress` каждые 30 сек → сервер отвечает 401 UNAUTHORIZED («Токен не предоставлен») → `progress_service.dart` молча проглатывает ошибку в try/catch (как и задумано — Apple HIG: не прерывать UX фоновыми операциями) → прогресс не сохраняется.

**Подтверждение из логов сервера:**
```
error: Unhandled error: Токен не предоставлен {"code":"UNAUTHORIZED"...}
```

**Это НЕ баг 2.7.** Код плеера правильный. Это **правильное поведение** системы для незалогиненного юзера.

**Где `ApiClient` (`app/lib/core/network/api_client.dart`):**
- Умеет добавлять `Authorization: Bearer <token>` если есть токен в SecureStorage
- Умеет refresh JWT на 401
- Если токена нет (юзер не залогинен) — заголовок не добавляется, сервер отбрасывает

**Временное решение для тестирования:** зарегистрироваться через приложение (email/пароль), 5 минут. Тогда прогресс работает.

**Полное решение:** задача 1.8.

## 🔠 КАТЕГОРИИ — РАЗДЕЛЕНИЕ БД И UI (13.05.2026)

**Решение:** капс категорий хранится в БД, sentence case показывается на UI через `BookCategories.labelFor()`.

**Архитектура:** `app/lib/core/constants/book_categories.dart` теперь содержит `Map<String, String> _labels` (приватный). Геттер `all` возвращает ключи карты (значения в БД капсом — для фильтрации), метод `labelFor(value)` возвращает sentence-case label для UI.

**Используется:**
- `category_chips.dart`: `label: BookCategories.labelFor(category)` — отображение чипа sentence case, фильтрация по исходному капсу.

**Важно для будущих задач:** когда поиск/опрос при онбординге начнут отображать категории — использовать `labelFor()`. Не выводить `book.categories` (массив капсом из БД) напрямую в UI.

**Почему так, а не миграция БД:** Анна добавляет книги через админку с капсом (5 лет привычки). Миграция значений в БД сломает синхронизацию с её рабочим процессом. Разделение БД/UI — стандартный паттерн i18n.
