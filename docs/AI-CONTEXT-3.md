## 🔑 СОГЛАСОВАННАЯ МОДЕЛЬ ПОДПИСОК И ДОСТУПА (15.06.2026) — ВАЖНО

Долго и подробно проработана с юзером. Это финальное решение (цены могут двигаться).

### Приложение и оплата
- **Приложение БЕСПЛАТНОЕ на скачивание + встроенные покупки (IAP).** В сторе пометка «Бесплатно · Встроенные покупки». В App Store Connect цена приложения = Free; продукты IAP — со своими ценами. Платное-на-скачивании НЕ подходит.
- Всё, что покупается **в iOS-приложении** → ТОЛЬКО через Apple IAP (комиссия 15% Small Business / 30%). Никаких ссылок «оплати на сайте» внутри iOS (реджект 3.1.1). Цену в приложении закладывать выше, чтобы покрыть комиссию.

### Тарифы (subscription group «Клуб ЧИТАТЕЛЬ»)
- **Месяц** — `club.basic.monthly`, авто-подписка, ~$28. Основной тариф.
- **Сезон (3 месяца)** — `club.basic.season`, авто-подписка, ~$54. Apple-период «3 месяца» (штатный). Автопродление сохраняем (важно для удержания — не теряем людей между сезонами).
- **«Навсегда»** = `archive.forever`, non-consumable (разовая), не подписка. Позже.
- **Премиум** — позже, в ту же группу как `club.premium.*` (Apple сам upgrade/downgrade).
- ⚠️ **Сезоны НЕ делаем как отдельные продукты на каждый сезон и НЕ через non-renewing.** Один продукт «3 месяца» с автопродлением. «Лето/осень/зима» — это НАЗВАНИЕ и КОНТЕНТ, не отдельные Apple-продукты.

### Сезонность — как реализуется (всё на НАШЕМ сервере, не Apple)
- **Окно продажи сезона** — серверная логика: сезонный тариф показывается на paywall только в начале сезона (правило: первый месяц каждого сезона — лето=июнь, осень=сен, зима=дек, весна=мар). Вне окна — только месячный. Сервер сам открывает/закрывает по календарю, продукт в Apple — один, ничего «каждый раз прописывать» в Apple не надо.
- **Название сезонное** на paywall + честные условия рядом («Сезон · 3 месяца · продлевается автоматически») — Apple ОК.

### Правило доступа к контенту (НАШ сервер; Apple только «платит/не платит»)
- **Контент — помесячные клубы**, старт 1-го числа, ОБЩИЕ для всех активных (один чат, одна книга месяца). Сезон = единица ОПЛАТЫ, месяц = единица КОНТЕНТА (внутри сезона 3 месячных клуба подряд).
- **Доступ активного = скользящее окно «текущий месяц + предыдущий месяц»** (предыдущий = архив на **31 день** хвоста). Глубже прошлого месяца — закрыто (даже активному; если захотим «весь архив активным» — это другое правило, решить позже).
- **«+31 день» хвоста** — часть подписки, входит в неё. (Было 21 на сайте → решили 31. См. правку кода ниже.)
- **Деньги — по личной дате Apple** (у каждого своя дата продления, от покупки). **Контент — по календарю** (наш сервер, общий для всех). Они НЕ совпадают по датам — это норма. Доступ привязываем к календарным клубам месяца, НЕ к «30 дням от покупки».
- Купил в середине → не обделён: Apple даёт полный оплаченный период от даты покупки + 31 день хвоста; в общий контент попадает сразу.
- Отписался → Apple держит до конца оплаченного периода, последний месяц ещё 31 день, дальше нет.

### Что НЕЛЬЗЯ через Apple (остаётся сайту)
- **Предпродажа заранее** (продать летний сезон весной): авто-подписка стартует и списывает В МОМЕНТ покупки, отложить старт на 1-е число нельзя. Окно продажи сезона = в начале самого сезона, не раньше. Предоплата «за лето весной» — ТОЛЬКО сайт.
- Рассрочка, подарочные сертификаты, оплата российскими/любыми картами — только сайт.

### Анонсы и пуши
- **Анонс будущего клуба/сезона МОЖНО заранее** (это наш контент, Apple не регулирует). В модели уже есть статус `future` (API клуба: `{archive, current, future}`).
- Граница: анонсировать заранее — да; продавать/списывать за будущий период через Apple — нет (только со старта). На анонсе допустима кнопка «Напомнить»/«Записаться» (это НЕ оплата).
- **Анонс нового клуба месяца → broadcast-пуш ВСЕМ** (регулярное событие). «Напомнить» — для разовых/сезонных запусков. Слать только тем, кто разрешил уведомления (настройки в профиле `profilePushSettings` уже есть). Реализация пушей — **Фаза 6**.

## 🧩 БУДУЩАЯ ФИЧА: КОДЫ АКТИВАЦИИ (Россия/Беларусь + предпродажа + штучные продажи) — ПРИОРИТЕТ ВЫСОКИЙ

⚠️ Не v1 по коду, но это КАНАЛ №1 ПО ДЕНЬГАМ (основная аудитория РФ+РБ не может платить через Apple). Требует поднятого сервера.

- **Зачем:** (1) Россия/Беларусь — Apple-оплата для их карт НЕ работает, продаём на сайте; (2) предпродажа сезона заранее; (3) отдельные разборы/пакеты вне Apple.
- **Как:** человек платит на сайте (карты, рассрочка) → получает **код** → вводит в приложении в нейтральном поле «Активировать код» → наш сервер открывает доступ (разбор/пакет/сезон). Можно для ЛЮБОГО разбора и клуба (ложится на product-agnostic `Purchase`).
- **Правило Apple (жёстко):** в приложении ТОЛЬКО нейтральное поле «активировать код», БЕЗ рекламы покупки на сайте, без кнопок/намёков «купи на сайте», БЕЗ гео-показа «россиянам — на сайт». Поле одинаковое для всех. Продажа и реклама — снаружи (рассылки, Telegram, сайт). Так живут Kindle/Spotify — легально.
- **Код = не Apple-подписка → без автопродления** (для росс./бел. карт это и так неизбежно). Следующий сезон — покупают заново.
- **Объём:** новая модель `ActivationCode` (код → товар → срок → использован/кем) + экран активации + связка с оплатой сайта. Связка: сначала ВРУЧНУЮ (менеджер выдаёт код после оплаты), потом авто-интеграция платёжки сайта с нашим API.

## УРОКИ (#28+; #1-27 в AC/AC-2)

**#28 — формат/версию пакета проверять по registry перед использованием.** `@apple/app-store-server-library` 3.1.0, CJS (main dist/index.js, без type:module) → require ок. API сверен по докам, не по памяти. Продолжение #21/#22/#27.

**#29 ⚠️ Apple-подписка: старт = момент покупки, период = от даты покупки (15.06).** Нельзя отложить старт (предпродажа «за лето весной» через Apple невозможна → сайт). Нельзя «календарный сезон для всех» на авто-подписке (у каждого своя дата). Решение: деньги по дате Apple / контент по календарю (наш сервер); сезонность = окно продаж + название + контент, НЕ отдельные продукты и НЕ non-renewing.

**#30 — активация контента, купленного вне приложения, легальна (Kindle/Spotify-модель), НО только нейтральное поле «активировать код», без рекламы внешней покупки в приложении (15.06).**

**#31 ⚠️ ГЛАВНОЕ СТРАТЕГИЧЕСКОЕ (16.06): Apple-оплата НЕ работает в РФ и Беларуси (карты не принимаются с 2022).** Основная аудитория проекта — РФ+РБ+Грузия. Через Apple платит только Грузия/Украина/Казахстан/заграница. Значит Apple-подписки покрывают МЕНЬШУЮ часть аудитории; основной денежный канал — САЙТ + КОДЫ АКТИВАЦИИ. Цены в Apple для РФ/РБ бессмысленно выравнивать (там не оплатят). Не выравнивать цены по 175 странам — это тупик из-за разных НДС/округлений; единая честная цена даётся на сайте.

**#32 — ценообразование Apple (16.06):** витрина = НДС страны + комиссия Apple + твои поступления (Proceeds). Цены берутся из фикс. «ценовых точек» (не любое число; $27.99 для подписок может не быть → $28.99). США показывает цену БЕЗ налога (налог штата сверху у покупателя), многие страны (Грузия и т.п.) — С НДС внутри + округление вверх → витрина выглядит дороже, но Proceeds сопоставимы. Ориентир — колонка Proceeds, не витрина. Базовую страну ставить США/USD (не Грузию — иначе всё едет вверх). Отдельные страны переопределять вручную точечно. До одобрения Small Business матрица считает Proceeds по 30%, после — 15%.

**#33 — продукты-разборы через ASC API (16.06):** создание non-consumable через POST /v2/inAppPurchases официально поддерживается, но API капризный: цены отдельным эндпоинтом inAppPurchasePriceSchedules через price points (бывают 500), скриншоты обычно руками. Не «за 5 минут» — отдельная инженерная задача. Сначала проверить покупки на 1-2 продуктах, потом массово. ID навсегда — не ошибаться в Product ID при массовом прогоне.

**#34 ⚠️ ПРОЦЕСС: при обновлении AI-CONTEXT через GitHub MCP ВСЕГДА отдавать ПОЛНЫЙ файл (сначала get_file_contents → дописать → запушить целиком), НИКОГДА не слать только новый кусок (16.06).** Один раз случайно затёр AC-3 (30KB→1.6KB) одним абзацем; восстановил из истории git (коммит `265f8b9`). create_or_update_file ПЕРЕЗАПИСЫВАЕТ весь файл, а не дополняет.
