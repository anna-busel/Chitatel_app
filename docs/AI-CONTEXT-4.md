## 1. Что сделано в этом чате (всё в main)

### 1.1 Live-«Куплено» в каталоге + фикс restore-транзакции (главное)

Симптом: после покупки разбора с карточки и возврата в каталог «Куплено» не
появлялось до ручного refresh (свайпа). Внутри карточки разбора статус
обновлялся, в каталоге — нет.

Диагностика (сервер корректен, гонки нет):
- `GET /api/books` (optionalAuth) уже отдаёт вычисляемое `isOwned` по каждому
  разбору (`server/src/routes/books.js`, `ownedBookIdsFor` + `markOwned`):
  куплен отдельно (`purchasedBooks`) ИЛИ в составе купленного пакета
  (`purchasedPackages`). Подписка сюда НЕ входит (это не «покупка»).
- `POST /api/purchases/verify` пишет `purchasedBooks`/`purchasedPackages`
  синхронно через `await user.save()` ДО ответа клиенту
  (`purchase.service.js`), поэтому немедленный reload каталога видит свежие
  данные. Клиент шлёт токен через dio-интерцептор, кэша нет.
- Каталог — `catalogProvider` (StateNotifier, НЕ autoDispose); `CatalogScreen`
  его watch-ит; на success покупки экраны уже звали
  `catalogProvider.notifier.load()`.

Настоящая причина: ветка `PurchaseStatus.restored` в
`product_purchase_provider.dart` только завершала транзакцию (`complete()`) и
НЕ меняла состояние. StoreKit присылает non-consumable как `restored` при
повторной покупке того же товара в Sandbox (типичный кейс при тестах) — тогда
`success` не эмитился, экраны каталог не перечитывали. Карточка разбора при
этом показывала «Слушать», т.к. сервер помнил покупку с прошлого раза; каталог
обновлялся только вручную.

Фикс (модель безопасности НЕ менялась — restored по-прежнему НЕ верифицируется
и НЕ привязывается повторно, только `complete()`):
- `enum ProductPurchaseStatus` — добавлен `restored`.
- В ветке restored после `complete()` выставляется
  `state = ProductPurchaseState(status: restored, productId: ...)`.
- `book_screen.dart`, `package_screen.dart`, `paywall_sheet.dart` обрабатывают
  `restored` так же, как `success`: перечитывают книгу/пакет, историю покупок,
  каталог (`catalogProvider.load()`), `packagesProvider`. Тост при restore —
  «Покупка восстановлена». На холодном старте эти экраны не смонтированы, так
  что авто-restore StoreKit при запуске лишних тостов/обновлений не даёт.
- Заодно убран случайный символ «微» в комментарии `book_screen.dart`.

Файлы: `app/lib/features/payments/providers/product_purchase_provider.dart`,
`app/lib/features/book/screens/book_screen.dart`,
`app/lib/features/catalog/screens/package_screen.dart`,
`app/lib/features/player/widgets/paywall_sheet.dart`.
Коммиты в main: `b6af2c7` (provider + paywall), `f81eca9` (package_screen),
`0cb480f` (book_screen). Проверено побайтово через blob-SHA: provider, paywall,
package_screen идентичны локальным; book_screen отличается только длиной
декоративных «─» в комментариях (на компиляцию не влияет).

### 7.3 Гейт показа

- Интро-слайды — локальный `onboarding_seen` (как было).
- Персонализация — серверный `User.onboardingCompleted` (переживает
  переустановку/второе устройство). При входе `auth._saveAuthData` кладёт
  локальный `onboarding_pending = !onboardingCompleted`; редирект роутера держит
  юзера в цепочке, пока флаг взведён; опрос при отправке ставит
  `onboardingCompleted=true` (в т.ч. при «Пропустить») и снимает флаг; push-экран
  тоже снимает. Вариант А: повторно не переспрашиваем.
- **Существующие аккаунты**: `onboardingCompleted` у них нет → онбординг
  покажется при СЛЕДУЮЩЕМ входе (fresh sign-in даёт user-map с флагом). Уже
  залогиненные по сохранённому токену без перезахода онбординг НЕ увидят —
  для теста на старом аккаунте нужно выйти и войти заново.

### 7.4 Имя в ИИ-анализе + прокидка опроса (п.3 Гио)

Причина «анализ не обращается по имени»: Apple отдаёт имя только при ПЕРВОЙ
авторизации; иначе сервер писал заглушку `Пользователь`, она и уходила в промпт.
Теперь `ai.service.displayName()` заглушку/пустое → '' (промпт обращается на
«вы»), а экран «Имя» даёт настоящее. Плюс `ai.service.buildUserContext()`
заполняет плейсхолдер `{userContext}` разбора цитаты из ответов опроса
(ситуация, книга детства, вопрос сейчас, желание на год). Отчёты (weekly/monthly)
тоже поправлены: `ai.service.reportName()` = настоящее имя, а если его нет —
нейтральное «читательница» (пустое сломало бы шаблон «Дорогая {userName}»). Сам
контекст опроса в отчёты не подмешиваем — они и так строятся из цитат юзера, а
менять текст промптов Анны без спроса не стали.

админ), /:id/ban (нельзя банить админа). Пишет ТЕ ЖЕ денормализованные поля User,
что реальная покупка → доступ в приложении появляется сразу, без пересборки.

### 8.2 Каталог (`routes/admin-catalog.js` → `/api/admin/catalog`)

CRUD разборов. GET /categories — фикс. 14 категорий (значения КАПСОМ, совпадают с
`book_categories.dart` для точной фильтрации). POST/PATCH book: авто-slug
транслитом из title (ИММУТАБЕЛЕН после создания — к нему привязаны имена файлов),
`appleProductId = book.<slug>` для платных / null для бесплатных. POST /:id/cover —
обложка в `<AUDIO_BASE_PATH>/book-covers/<slug>/<uuid>.<ext>`, отдаётся signed URL
(image.service, фикс. exp 2099 → стабильный кэшируемый URL), `Book.coverImageUrl` =
этот https-URL (приложение уже умеет `Image.network`, см. BookCoverImage). POST
/:id/audio — аудио-часть в `<slug>/part-<N>.<ext>`, длительность через `ffprobe`
(есть на VPS, 6.1.1), апсерт части + пересчёт durationTotal; повтор с тем же
номером заменяет файл. DELETE /:id/audio/:n, DELETE /:id (только если не в клубе).
POST /:id/publish (нельзя публиковать без аудио-частей).

⚠️ Обложки и аудио пишутся на СЕРВЕР (AUDIO_BASE_PATH), НЕ в гит. Синхронизации с
GitHub нет и не требуется: гит = только код, контент (БД + файлы) живёт на VPS.

### 8.3 Клуб месяца (`routes/admin-club.js` → `/api/admin/club`)

CRUD ClubMonth: выбор книги из каталога, даты (date-picker), partSchedule
(необязательно; пусто = все части со старта). archiveUntilDate считается через
`archiveWindowEnd` (месяц клуба + весь следующий, синхронно с middleware).
month/year шлём с клиента из даты начала. Активность клуба определяется ДАТАМИ
(как читает routes/club.js: startsAt ≤ now ≤ endsAt), isActive держим в синхроне.
Проставляет `Book.isPartOfClub`/`clubMonth` (книга клуба уходит из «популярное/
бесплатное»); при смене книги снимает флаг со старой, если она больше нигде не
используется.
