## 1. Что сделано в этом чате (всё в main)

### 1.1 Live-«Куплено» в каталоге + фикс restore-транзакции (главное)

Симптом: после покупки разбора с карточки и возврата в каталог «Куплено» не
появлялось до ручного refresh (свайпа). Внутри карточки разбора статус
обновлялся, в каталоге — нет.

Диагностика (сервер корректен, гонки нет):
- `GET /api/books` (optionalAuth) уже отдаёт вычисляемое `isOwned` по каждому
  разбору (`server/src/routes/books.js`, `ownedBookIdsFor` + `markOwned`):
  куплен отдельно (`purchasedBooks`) ИЛИ в составе купленного пакета
  (`purchasedPackages`). Подписка сюда НЕ входит (это не «покупка»).
- `POST /api/purchases/verify` пишет `purchasedBooks`/`purchasedPackages`
  синхронно через `await user.save()` ДО ответа клиенту
  (`purchase.service.js`), поэтому немедленный reload каталога видит свежие
  данные. Клиент шлёт токен через dio-интерцептор, кэша нет.
- Каталог — `catalogProvider` (StateNotifier, НЕ autoDispose); `CatalogScreen`
  его watch-ит; на success покупки экраны уже звали
  `catalogProvider.notifier.load()`.

Настоящая причина: ветка `PurchaseStatus.restored` в
`product_purchase_provider.dart` только завершала транзакцию (`complete()`) и
НЕ меняла состояние. StoreKit присылает non-consumable как `restored` при
повторной покупке того же товара в Sandbox (типичный кейс при тестах) — тогда
`success` не эмитился, экраны каталог не перечитывали. Карточка разбора при
этом показывала «Слушать», т.к. сервер помнил покупку с прошлого раза; каталог
обновлялся только вручную.

Фикс (модель безопасности НЕ менялась — restored по-прежнему НЕ верифицируется
и НЕ привязывается повторно, только `complete()`):
- `enum ProductPurchaseStatus` — добавлен `restored`.
- В ветке restored после `complete()` выставляется
  `state = ProductPurchaseState(status: restored, productId: ...)`.
- `book_screen.dart`, `package_screen.dart`, `paywall_sheet.dart` обрабатывают
  `restored` так же, как `success`: перечитывают книгу/пакет, историю покупок,
  каталог (`catalogProvider.load()`), `packagesProvider`. Тост при restore —
  «Покупка восстановлена». На холодном старте эти экраны не смонтированы, так
  что авто-restore StoreKit при запуске лишних тостов/обновлений не даёт.
- Заодно убран случайный символ «微» в комментарии `book_screen.dart`.

Файлы: `app/lib/features/payments/providers/product_purchase_provider.dart`,
`app/lib/features/book/screens/book_screen.dart`,
`app/lib/features/catalog/screens/package_screen.dart`,
`app/lib/features/player/widgets/paywall_sheet.dart`.
Коммиты в main: `b6af2c7` (provider + paywall), `f81eca9` (package_screen),
`0cb480f` (book_screen). Проверено побайтово через blob-SHA: provider, paywall,
package_screen идентичны локальным; book_screen отличается только длиной
декоративных «─» в комментариях (на компиляцию не влияет).

## 4. План до публикации в Apple (порядок)

Приоритетная цепочка: **онбординг → push → админка.**

1. **Онбординг + опрос (6.3).** Кода нет, только спека (MASTER/STEP-BY-STEP).
   7 вопросов, предзаполнение имени из Apple/Google, согласие на ИИ (opt-in) и —
   критично — сюда встроить запрос разрешения на push (сейчас он только кнопкой
   в настройках).
2. **Push (6.1) + лента уведомлений (4.30).** Клиент готов, ждёт серверный
   APNs `.p8` от Анны (попросить параллельно с онбордингом). Лента + возврат
   колокольчика — в этой же связке.
3. **Админка (единая).** Доращивание: Книги, Клуб, Аудио, Push, «Мысль дня»,
   ручная выдача доступа.

Параллельно, не блокируя цепочку, — независимые задачи под сабмит:
- скрыть кнопку Google;
- каталог УЖЕ опубликован (по diag-catalog этой сессии: ~55 разборов + 8
  пакетов видимы, у всех есть аудио; 5 недоделанных скрыты). Осталось только
  проверить теги/категории для ИИ-рекомендаций (не блокер ревью);
- дозаполнить IAP-метаданные (64 покупки + 2 подписки в MISSING_METADATA),
  отправить на ревью ВМЕСТЕ с билдом;
- завести рабочую почту `support@chitatel.app` (смена = пересборка);
- перед релизом переключить `APPLE_ENVIRONMENT` → `production`.

Гигиена перед релизом: сменить засветившийся пароль админа (`anna123456`),
поднять Node на VPS до ≥20, проверить юр-реквизиты в legal.

После публикации: Google-вход целиком, коды активации РФ/РБ, accessibility
(6.4), error-states (6.5), rate limiting, ротация секретов.
