# Как выложить новую версию ЧИТАТЕЛЯ (iOS)

Процедура выпуска обновления. Проверена на 1.0.1 (26.08.2026).
Сборка — Codemagic (Mac не нужен), публикация — App Store Connect.

## Шаг 0. Код готов в main

- Все правки версии залиты в ветку `main`.
- Подняты номера в ДВУХ файлах:
  - `app/pubspec.yaml` → `version: 1.0.X+1`
  - `codemagic.yaml` → `--build-name=1.0.X`
- Номер билда (build number) руками не трогать — Codemagic сам берёт
  последний из TestFlight и прибавляет 1.

## Шаг 1. Собрать

codemagic.io → Chitatel_app → **Start new build** → ветка `main`,
workflow **iOS TestFlight** → Start. 15–25 минут.

Зелёная галочка = билд сам ушёл в App Store Connect (публикация в конфиге).
Красный крест = смотреть лог шага, на котором упало.

## Шаг 2. Создать версию в App Store Connect

Можно параллельно со сборкой.

My Apps → ЧИТАТЕЛЬ → в колонке версий у iOS кнопка **«+»** → ввести номер
(`1.0.X`) → Create. Тексты, скриншоты, рейтинг — унаследуются от прошлой
версии, заново ничего не заполняется.

## Шаг 3. Два поля на странице версии

1. **«Что нового в этой версии»** — 1–3 строки для пользователей, по-русски,
   без технических терминов.
2. **Релиз версии** → **«Выпустить эту версию вручную»**.
   ⚠️ По умолчанию стоит автоматический — проверять каждый раз
   (1.0 уехала в магазин сама именно из-за этого).

## Шаг 4. Дождаться обработки билда

После сборки Apple обрабатывает файл 10–40 минут. Готовность видна в
разделе TestFlight (статус перестаёт быть Processing) + приходит письмо.

## Шаг 5. Проверить на телефоне

Приложение TestFlight → ЧИТАТЕЛЬ → Установить/Обновить → пройти глазами
именно то, что менялось в этой версии. TestFlight-сборка заменяет
магазинную копию на телефоне — это нормально, данные и логин сохраняются;
когда версия выйдет в магазин, телефон сам обновится на магазинную.

Покупки в TestFlight-сборке идут через песочницу (деньги не списываются).
⚠️ Не покупать подписку под чужими app-аккаунтами на личном телефоне —
история с зомби-транзакциями, см. AI-CONTEXT-5 раздел 14.3.

## Шаг 6. Прикрепить билд и отправить

Страница версии → блок «Сборка» → выбрать свежую → Save →
**«Добавить для проверки» / «Отправить на проверку»**.

- Новые покупки, если есть, подаются в том же черновике отправки.
- `club.basic.season` и прочие «сезонные» продукты в отправку версии не
  добавлять, если их нельзя купить в приложении прямо сейчас.

## Шаг 7. Ждать проверку

Обновления проверяются от пары часов до суток. Отказ или вопрос —
разбирать по тексту письма, отвечать в тред App Review (новая сборка
нужна только если требуется правка кода).

## Шаг 8. Выпустить

После Approved на странице версии появляется **«Выпустить эту версию»**.
Нажать в удобный момент (можно приурочить к анонсу). Пользователи получат
обновление автоматически в течение 1–2 дней.

## Шаг 9. После выпуска

- Проверить номер версии в карточке App Store.
- Если чинили видимую проблему — попросить жаловавшегося перепроверить.
- Дописать итог версии в актуальный AI-CONTEXT.

## Что НЕ требует новой версии

Живёт на сервере и меняется без сборки:

- контент клуба, книги, части, расписания — админка;
- обложки книг — файлы на сервере + coverImageUrl в базе;
- цены продуктов, новые покупки/подписки — App Store Connect
  (после первой публикации подаются отдельно от версий);
- юридические страницы (privacy/terms/support) — git pull на VPS;
- промотекст в карточке App Store — меняется без ревью в любой момент.
