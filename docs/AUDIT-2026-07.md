## БЛОК C — ПОСЛЕ ПОДАЧИ (v1.0.x–v1.1, НЕ блокеры)

### C1. ⬜ 🟡 Rate limiting на контент-эндпоинты
Сейчас limiter ТОЛЬКО на `/api/auth`. POST чата/картинок/реакций/жалоб/Q&A — без лимитов (флуд, заливка диска 8МБ×N, накрутка жалоб). Фикс: общий limiter на `/api` (~300/мин/IP) + строгий на upload (~10/мин/юзер) + на report (~5/час/юзер). Webhook Apple limiter'ом НЕ накрывать.

### C2. ⬜ 🟡 `resolveClubAccess` на reaction (и проверка клуба в PATCH/DELETE)
`POST /chat/:messageId/reaction` — в комментарии кода написано «нужен resolveClubAccess», в цепочке middleware его НЕТ. Любой залогиненный free-юзер реагирует на сообщения любого клуба по ID. Однострочный фикс + аналогичная проверка принадлежности сообщения клубу юзера в PATCH/DELETE/report.

### C3. ⬜ 🟡 Хэшировать refresh-токены в БД
`user.refreshTokens = [raw JWT]` — при утечке дампа Mongo токены рабочие. Хранить SHA-256 хэш, сравнивать хэш. (Rotation + reuse-detection уже реализованы правильно — не трогать.) Заодно: обрезка до 5 токенов есть только в `login` — добавить в apple/google/refresh пути.

### C4. ⬜ 🟡 Magic-bytes проверка загрузок
MIME проверяется по заголовку клиента (`req.file.mimetype`). Добавить проверку содержимого (пакет `file-type`) + убедиться что `X-Content-Type-Options: nosniff` действует на `/images` (helmet стоит на приложении — проверить покрытие статики).

### C5. ⬜ 🟠 `readBy[]` — исключить из выдачи чата (и заложить миграцию)
При росте до тысяч подписчиц `readBy` раздует документы ChatMessage. Минимум сейчас: исключить `readBy` из select в GET /chat и /context. При реальном росте — счётчик + отдельная коллекция.

### C6. ⬜ 🟠 Индексы
Проверить/добавить: `ChatMessage {clubMonthId:1, createdAt:-1}`, `Purchase {transactionId:1}` (unique), `Report {status:1, createdAt:-1}`.

### C7. ⬜ 🟠 `express.json` limit 10mb → вниз (например 200kb глобально; multipart-роуты не зависят от json-лимита).

### C8. ⬜ 🟠 Аудио через nginx (`X-Accel-Redirect` или `secure_link`)
Сейчас Range-стриминг идёт через Node — при сотнях параллельных стримов event loop занят файлами, чат в том же процессе начнёт лагать. ~Полдня работы. Делать при реальной аудио-нагрузке.

### C9. ⬜ 🟠 Мелочь по масштабу: Q&A антидубль O(n) (грузит все вопросы клуба в JS); reactions read-modify-write (возможна потеря при одновременных реакциях — перевести на атомарные `$pull`/`$addToSet`).

### C10. ⬜ 🟠 Гигиена: `.gitignore` (`audio-storage/`, `.env*`, удалить `app/-H app/-d`) — **проверить историю git: если `.env` когда-либо коммитился → ротация всех секретов**; маскировать Mongo-пароль в логах seed; офлайн-кэш аудио в v1.1 (разгрузка трафика VPS).
